Can CodeSignal leave pilot?

A hands-on product assessment of the shipped CLI. First published 16 Aug 2026; this page is the current leave-pilot evidence, not a historical snapshot. Gap ids stay stable — closed items move to the archive below, they are not deleted.

Last reviewed 31 Aug 2026 HEAD e5bfa4a ~55 CLI runs 6 repositories 4th verification pass #282 · 5 / 24 closed

Verdict

Stay in pilot.

Not because the analysis is bad. The engine is faster and more honest than it was on 16 August. The blocker is narrower and sharper: a new file’s findings are still counted as zero introduced, with no diagnostic. A rename is still not analyzed — the headline now admits the skip, but the machine summary still says the change introduced nothing. Diff mode is the capability that would make this a PR check. It still cannot tell a customer what a typical AI-assisted change introduced.

The honesty fix changed the presentation of visible skips. It did not change the job. Do not expand to a named advisory PR-check audience. The current self-serve Go pilot can keep using baseline and configured layer policy.

Blockers · ranked

Gaps that still keep this in pilot

G1

A new file’s findings are counted as zero introduced

re-verified

This is now the sharper blocker: the remaining silent path, and the dominant agent-authored shape. One commit adds one valid Go file. The tool finds four signals — then classifies them unknown and reports introduced_signals: 0. No diagnostic. Coverage looks complete.

$ coach codesignal --base HEAD~1 --format json "summary": { "files_analyzed": 1, "active_signals": 4, "introduced_signals": 0, "existing_signals": 0, "resolved_signals": 0 } unknown complexity.cognitive_complexity brandnew.go =56 unknown complexity.max_nesting_depth brandnew.go =9 unknown state.hidden_input_mutation brandnew.go m["x"]

The README defines introduced as “present at HEAD, not present at the merge-base” and unknown as “the merge-base side could not be analyzed.” An added file is definitionally introduced. The shipped behavior contradicts both sentences. Counters still do not sum: four active, every bucket zero.

The composite is worse. Add a risky file and delete another: introduced: 0, resolved: 1 — a strictly worse change reading as a pure win. Any CI gate written fail if introduced_signals > 0 passes it.

Who it hurts: every consumer of diff mode — and worst for the customer the PRD names, someone reviewing agent-generated code where new files dominate. Why it outranks the rename skip: a careful human now sees a qualified headline on a rename; they see nothing wrong here.

Root cause

One table still explains the blocker

Diff mode’s correctness is still a function of how git labels the change. Two of the four labels mishandle toward silence. G0 used to be a third mechanism; it is closed.

Git statusAnalyzed?Lifecycle assignedCounted asShould be
M — modifiedyesintroduced / existingcorrectly✓ correct
D — deletedyesresolvedresolved✓ correct
A — addedyesunknownnothingintroduced
R / C — renamedno—nothingintroduced / existing

The two rows that fail are the two that dominate agent-authored diffs. The R/C headline is now qualified. The A row still has no diagnostic. Machine consumers still see introduced: 0 on both.

Working

What the pilot has already earned

  • Determinism and speed. Three identical production runs hash identically. Baseline over 720 tracked files in 1.02s production / 1.57s all-scope. learn-go-with-tests (304 files) in 0.56s. No crashes, no hangs on six repos.
  • Fingerprint stability is the hard part, and it’s right. Inserting a comment above flagged code produced 3 findings, all existing, zero false introduced.
  • --build-target is still the best idea in the product. It cut 281 files / 250 signals down to 118 / 141. “This code actually ships in the artifact” is defensible in a way “this file has branch_sum=68” is not. It is still a silent no-op under --scope all.
  • Configured layer policy is the highest-quality output — and now there are two of them. architecture.layer_violation and Go architecture.layer_bypass: exact edge or path, exact line, machine-readable evidence, a policy the user declared.
  • Incomplete analysis is disclosed when the skip is visible as a diagnostic. Config failures fail closed. Usage errors stay off stdout. Empty JSON collections stay present.
  • The TOCTOU recommendation is still what actionable looks like — CWE-367, concrete Go API names, errors.Is(err, fs.ErrNotExist), a pointer to os.Root.

Survivable

Ship with a caveat rather than fix first

  • Security-rule recall is still not a completeness claim. Supported if-init Stat/Lstat+Open fire; TypeScript existsSync+read and write-side fire. Missed: the idiomatic Go guard-clause, os.IsNotExist, Go write-side Create/Rename, TypeScript negated guard. Do not put the word “security” in front of a customer. #205
  • A dirty working tree is silently ignored. Staged and untracked mutations are invisible and can print a clean all-clear. Correct by design — analysis reads committed bytes — and still confusing. #265 #168
  • --scope all --build-target is byte-identical to --scope all. Filter policy and classifier evidence are still conflated. #283
  • Positional args still swallow every flag after them. --baseline foo bar --format json returns text, exit 0, empty stderr. #273
  • The PRD rule inventory is more stale, not less — it still omits architecture.layer_violation, and now also omits the shipped Go architecture.layer_bypass. #274
  • source_sink_pack is still a reserved no-op that changes project fingerprints without changing findings. Documented; still a footgun.

Limits

Evidence that could not be obtained

These bound the verdict and should be read as unresolved, not as absent problems.

  • TypeScript project analysis on any repo but this one. --check-project now runs on a foreign TypeScript repo and can report ready with empty gaps. The following scan still fails honestly (project_backend_unavailable); file-local TypeScript still works. A layer report is still proved only inside this clone. In-repo parity is locked (#218). Obtain on a foreign repo is not. Do not read ready as obtain. #280
  • The released binary in a real CI runner. This pass used a locally built macOS/arm64 binary. Linux/Windows, container startup, and the signed-release path are unverified. #276
  • No systematic precision census. Still the gate the PRD names. 24% of findings still carry empty evidence and are not adjudicable. #260
  • The noise judgment is inferred, not observed. The 84% and 76% numbers are measurements; “a named team will not run this twice” is an inference from them.
