Can CodeSignal leave pilot?

A reading of the shipped CLI, made by running it. First published 16 Aug 2026. This page is the evidence for leaving pilot. It is not an old snapshot. Closed gaps move to the archive. They are not deleted. The ids stay.

Last reviewed 27 Sep 2026 HEAD 00aa40f ~96 CLI runs 6 repositories 23rd verification pass #282 · 8 / 24 closed

Verdict

Stay in pilot.

The analysis is not the reason. An added file counts as introduced. A rename or a copy is read at the new path. The finding is lifecycle: unknown, and the report carries continuity_not_determined, until old-path continuity exists. What still holds this in pilot is obtain, noise, and a report that is hard to use. The change itself is no longer skipped in silence. Do not sell diff mode as an advisory PR check until a named audience can be told an honest job on a fresh corpus.

Do not widen the audience on this restamp. The Go pilot that already runs can keep using baseline, a layer policy they wrote, and file-local diff mode on adds, modifications, deletes, renames, and copies.

Root cause

The diff table is no longer the blocker

Diff mode no longer depends on whether git labels the change A, M, D, R, or C. G0, G1, and G2 are closed. Statuses the CLI still does not analyze (T, U, X, B) are counted. They are not waved through as a clean report.

Git statusAnalyzed?Lifecycle assignedCounted asShould be
M — modifiedyesintroduced / existingcorrectly✓ correct
D — deletedyesresolvedresolved✓ correct
A — addedyesintroducedintroduced✓ correct
R / C — renamedyesunknown + continuity diagnosticunknown✓ analyzed; continuity not claimed

The four labels that dominate agent-authored diffs now analyze HEAD content. A pure rename is unknown. It is not introduced, and it is not existing. Continuity against the old path is still out of scope.

Working

What the pilot has already earned

  • Determinism and speed. Three identical production runs hash identically. Baseline over 720 tracked files in 1.02s production / 1.57s all-scope. learn-go-with-tests (304 files) in 0.56s. No crashes, no hangs on six repos.
  • Fingerprint stability is the hard part, and it’s right. Inserting a comment above flagged code produced 3 findings, all existing, zero false introduced.
  • --build-target is still the best idea in the product. It cut 281 files / 250 signals down to 118 / 141. “This code actually ships in the artifact” is defensible in a way “this file has branch_sum=68” is not. It is still a silent no-op under --scope all.
  • Configured layer policy is the highest-quality output — and now there are two of them. architecture.layer_violation and Go architecture.layer_bypass: exact edge or path, exact line, machine-readable evidence, a policy the user declared.
  • Incomplete analysis is disclosed when the skip is visible as a diagnostic, including a file-local dirty tree (worktree_changes_not_analyzed). Config failures fail closed. Usage errors stay off stdout. Empty JSON collections stay present.
  • Linux CI records an offline allowed-set for a TypeScript project scan — committed snapshot source, already-resolved host compiler and runtime files, Coach's own analyzer files, and ordinary system libraries, with no network during the scan. That observation is Linux-only. It is not a customer Mac proof, not a kernel sandbox, and not a claim the target TypeScript journey ships.
  • TypeScript project reports now name scope, provenance, and honest no-match next actions. Schema-2 JSON on this branch carries project_provenance (runtime.kind node, origin path, probed version), project_scope with the #281 inclusion gap, and ordered project_next_actions. A complete scan with no configured match says exactly that — not architectural compliance — then offers record_baseline and review_policy_coverage.
  • The TOCTOU recommendation is still what actionable looks like — CWE-367, concrete Go API names, errors.Is(err, fs.ErrNotExist), a pointer to os.Root.

  • Positional args still swallow every flag after them. --baseline foo bar --format json returns text, exit 0, empty stderr. #273
  • The PRD rule inventory is more stale, not less — it still omits architecture.layer_violation, and now also omits the shipped Go architecture.layer_bypass. #274
  • source_sink_pack is still a reserved no-op that changes project fingerprints without changing findings. Documented; still a footgun.
